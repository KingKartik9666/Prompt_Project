1. Goal of the algorithm

We are given a black-box (oracle) function f: {0,1}^2 -> {0,1} that is promised to be either constant (same output on all 4 inputs) or balanced (outputs 0 on exactly 2 inputs and 1 on the other 2), and we must decide which. Deutsch-Jozsa answers this with certainty using a single query to the oracle, whereas a deterministic classical algorithm needs 2^(n-1) + 1 = 3 queries in the worst case for n = 2.

2. Steps

For a concrete balanced example, take f(x1 x2) = x1 XOR x2, so f(00) = 0, f(01) = 1, f(10) = 1, f(11) = 0. We use 2 input qubits and 1 ancilla (output) qubit. The oracle acts as U_f |x>|y> = |x>|y XOR f(x)>.

Step 0 - Initialise.
Put the input qubits in |0> and the ancilla in |1>.
State: |00>|1>

Step 1 - Apply a Hadamard to every qubit (H tensor H tensor H).
Recall H|0> = (|0> + |1>)/sqrt(2) = |+> and H|1> = (|0> - |1>)/sqrt(2) = |->.
State: |+>|+>|-> = (1/2)(|00> + |01> + |10> + |11>) tensor |->
The input register is now an equal superposition of all 4 inputs, each with amplitude 1/2.

Step 2 - Apply the oracle U_f once.
Because the ancilla is |->, U_f|x>|-> = (-1)^f(x) |x>|-> (phase kickback: the value of f becomes a sign on |x>, and the ancilla is unchanged).
State: (1/2)( (-1)^f(00)|00> + (-1)^f(01)|01> + (-1)^f(10)|10> + (-1)^f(11)|11> ) tensor |->
For f = x1 XOR x2:
State: (1/2)( |00> - |01> - |10> + |11> ) tensor |->
This factors as |->|->|->, i.e. the input register is |-->.

Step 3 - Apply a Hadamard to each input qubit (H tensor H on the first two qubits; the ancilla can be ignored from here).
In general, (H tensor H)|x> = (1/2) sum_z (-1)^(x.z) |z>, so the amplitude of |z> after this step is (1/4) sum_x (-1)^(f(x) + x.z).
The amplitude of |00> is (1/4) sum_x (-1)^f(x) = (1/4)(1 - 1 - 1 + 1) = 0. This is 0 for every balanced f, because the +1 and -1 terms cancel exactly.
For our f, H|-> = |1> on each qubit, so:
State: |11> tensor |->

Step 4 - Measure the two input qubits in the computational basis.

3. Final measurement result with probabilities

For f(x) = x1 XOR x2:
P(00) = 0
P(01) = 0
P(10) = 0
P(11) = 1

The outcome is 11 with probability 1. The decision rule is: if the result is 00, f is constant; if it is anything other than 00, f is balanced. Since P(00) = 0 for every balanced function, the algorithm outputs "balanced" with certainty. (For a constant f, the same circuit gives 00 with probability 1.) Which non-zero string you get depends on which balanced function it is; for example, f(x) = x1 gives 10 with probability 1.

On speedup: for n = 2 this is 1 query versus 3 deterministic classical queries, a constant-factor saving. For general n, the gap is 1 versus 2^(n-1) + 1, which is exponential only against exact deterministic classical algorithms; a randomized classical algorithm that may err with small probability needs only a constant number of queries, so this is not an exponential speedup over all classical methods.

4. Common misconception

A common misconception is that the algorithm "computes f on all inputs at once and reads out all the values", when in fact the measurement reveals only one global property (constant vs balanced), produced by interference that makes the |00> amplitude cancel to zero for balanced functions.
