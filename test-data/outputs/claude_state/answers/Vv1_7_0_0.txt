Not quite. Grover's algorithm gives a quadratic speedup, not an exponential one.

- Classical search of an unstructured list of N items needs about N/2 oracle queries on average (N in the worst case).
- Grover's algorithm needs about (pi/4) * sqrt(N) queries.

So for N = 1,000,000, a classical search needs on the order of 500,000 queries, while Grover needs about 785. That is a big gain, but it is O(sqrt(N)) versus O(N), which is polynomial (quadratic), not exponential. It has also been proven (Bennett, Bernstein, Brassard and Vazirani, 1997) that no quantum algorithm can do better than order sqrt(N) for unstructured search, so Grover is optimal and an exponential speedup for this problem is impossible. Exponential speedups are known only for problems with special structure, such as factoring (Shor's algorithm).

How it works for 4 items (N = 4)

Setup: 4 items need 2 qubits, with basis states |00>, |01>, |10>, |11>. Suppose the marked item is |11>. The oracle is a black box that recognises the marked item.

Step 1 - Uniform superposition.
Start in |00> and apply a Hadamard gate to each qubit:
  |s> = (1/2)(|00> + |01> + |10> + |11>)
Every amplitude is 1/2, so each item would be measured with probability 1/4.

Step 2 - Oracle (phase flip).
The oracle multiplies the amplitude of the marked state by -1:
  (1/2)(|00> + |01> + |10> - |11>)
Measurement probabilities are unchanged (still 1/4 each), but the marked state is now "tagged" by its sign.

Step 3 - Diffusion operator (inversion about the mean).
The diffuser is D = 2|s><s| - I. Its effect on amplitudes is: new amplitude = 2 * (mean) - old amplitude.
  Mean of the amplitudes = (1/2 + 1/2 + 1/2 - 1/2) / 4 = 1/4
  Unmarked states: 2(1/4) - 1/2 = 0
  Marked state:    2(1/4) - (-1/2) = 1
Result: |11> with amplitude 1, all others 0.

Step 4 - Measure.
You get |11> with probability 1 (100%).

So for N = 4, one Grover iteration (one oracle call plus one diffusion) finds the marked item with certainty. A classical algorithm needs 2.25 queries on average (and up to 3 in the worst case, since if the first 3 checks fail the 4th must be the answer).

Geometric picture: think of a 2D plane spanned by the marked state and the uniform superposition of the unmarked states. The starting state makes an angle theta with the unmarked direction, where sin(theta) = 1/sqrt(N). Each Grover iteration (oracle reflection followed by diffusion reflection) rotates the state by 2*theta toward the marked state. For N = 4, sin(theta) = 1/2, so theta = 30 degrees; the start is at 30 degrees and one iteration rotates by 60 degrees to land at exactly 90 degrees, i.e. on the marked state. For general N you need about (pi/4) * sqrt(N) rotations, which is where the sqrt(N) scaling comes from. Doing too many iterations overshoots and the success probability drops again.

Caveats worth remembering:
- The speedup is in oracle queries; building the oracle for a real problem can itself be costly.
- Loading a classical database into a quantum state (e.g. QRAM) is not free and can erase the advantage for literal database search.
- On today's noisy hardware, error rates limit how many iterations can be run reliably.

Summary: Grover's algorithm is optimal and genuinely faster, but the speedup is quadratic (sqrt(N) versus N), not exponential. For 4 items it works perfectly in a single iteration.
