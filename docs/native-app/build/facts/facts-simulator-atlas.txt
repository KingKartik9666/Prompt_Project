6. Verifier rules (verify)
The rules below are applied in this order.
Tolerance: the pipeline calls verify(algo, probs, 0.02). The tolerance is absolute and applies to each outcome. [app/crates/desktop/src/pipeline.rs:102]
The claims are the &quot;probabilities&quot; field of the claim extractor&apos;s (P3) JSON. If it is missing, the claim is Null. [app/crates/desktop/src/pipeline.rs:99-101]
Ground truth = truth(algo), the rounded final distribution. [app/crates/qcore/src/lib.rs:520]
If the claim is a JSON object, each value goes through to_prob. A parsed value is added under norm_key(key), so keys that normalise to the same label are summed. A value that cannot be parsed gives the mismatch &quot;{key}: unparseable value {Python repr}&quot;. [app/crates/qcore/src/lib.rs:523-529]
A claim that is not an object (null, list, string, number) is treated as making no claims. [app/crates/qcore/src/lib.rs:523]
If nothing was claimed and nothing was unparseable, the mismatch is &quot;no final probability stated&quot;. [app/crates/qcore/src/lib.rs:532-534]
Deutsch–Jozsa only: [app/crates/qcore/src/lib.rs:535-550]
Truth is cut to {0…0: P(0…0)}. Only the all-zeros key is compared, and only if something was claimed. [app/crates/qcore/src/lib.rs:537-540]
Every claimed key must have n bits, else &quot;keys must be n-bit input-register strings, got [&apos;…&apos;]&quot;. [app/crates/qcore/src/lib.rs:541-544]
A sum check fails with &quot;claimed probabilities sum to X.XXX, expected 1&quot; when the sum exceeds 1 + tol, or when any non-zero key is claimed and |sum − 1| &gt; tol. [app/crates/qcore/src/lib.rs:545-549]
Comparison: for Bell and Grover, every key in truth ∪ claimed is compared; for Deutsch–Jozsa, only the all-zeros key. A missing value counts as 0. A mismatch is |t − c| &gt; tol, reported as &quot;{key}: claimed c, simulated t&quot;. [app/crates/qcore/src/lib.rs:531,551-556]
ok = no mismatches. [app/crates/qcore/src/lib.rs:557]
Key normalisation keeps only &apos;0&apos; and &apos;1&apos; characters, so &apos;|01&gt;&apos;, &apos; 01 &apos; and &apos;|0&gt;|1&gt;&apos; all become &quot;01&quot;. Code reading: a key with no 0/1 characters (e.g. &quot;x&quot;) becomes the empty label &quot;&quot;. [app/crates/qcore/src/lib.rs:395-398]

9. The content gate
The gate is cargo test -p qcore, specifically the test topic::tests::atlas_content_passes_the_gate. It loads sections.json and every topics/*.json file and fails on any problem. [app/crates/qcore/src/topic.rs:190-216; app/docs/atlas-spec.md:6]
What the gate checks:
Every file parses into the schema, and each file name equals its id. [app/crates/qcore/src/topic.rs:200-210]
Topic ids are unique and lowercase-kebab, and each topic&apos;s section exists. [app/crates/qcore/src/topic.rs:150-160]
Link integrity: every prereq, next and related id points at a topic file that exists, and no topic links to itself. [app/crates/qcore/src/topic.rs:161-170]
Each page has at least one text block. [app/crates/qcore/src/topic.rs:171-173]
Every circuit runs (valid gates, qubits, controls, angles), and expect.qubits is in range. [app/crates/qcore/src/topic.rs:113-120]
Every expect label has the right number of bits (0/1 only). The stated probabilities sum to 1 within 4 × TOL = 2e-3. [app/crates/qcore/src/topic.rs:125-135]
Every simulated outcome matches the stated value within TOL = 5e-4 (labels not stated count as 0). [app/crates/qcore/src/topic.rs:109-110,136-141]
The negative test gate_catches_a_wrong_claim_and_a_dead_link builds a topic with next = [&quot;nowhere&quot;] and a claim of 0.9/0.1 for H|0⟩. It asserts both &quot;missing topic nowhere&quot; and &quot;simulator gives 0.5&quot; errors. [app/crates/qcore/src/topic.rs:218-234]
