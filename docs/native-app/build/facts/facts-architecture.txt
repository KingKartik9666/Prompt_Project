Architecture at a glance
The app is one Windows GUI process. A frameless tao window hosts a WebView2 view through wry; the interface is Leptos compiled to WebAssembly, embedded in the exe and served over a private app:// protocol with &quot;no browser, no local web server, no open port&quot; (module comment) [app/crates/desktop/src/main.rs:1-5].
API keys stay in the native process; the comment states &quot;API keys stay in this process&quot; [app/crates/desktop/src/main.rs:5]. Only the last four characters of a key are sent to the web view [app/crates/desktop/src/llm/mod.rs:244-248] [app/crates/desktop/src/main.rs:96, 108].
All LLM network calls are made by the host with ureq, never by the page; the page&apos;s CSP limits connect-src to &apos;self&apos; [app/crates/desktop/src/main.rs:63].
The simulator crate qcore is compiled twice: into the host (claim verification in the pipeline) and into the WebAssembly UI (Lab, Atlas, Tutor visuals) [app/crates/qcore/Cargo.toml:3] [app/Cargo.lock:806-817, 3936-3945].

Module responsibilities
qcore/lib.rs: a statevector simulator for the three verifiable circuits (Bell, Deutsch-Jozsa, Grover-2) with real amplitudes in f64, step traces, and the claim verifier ported from code/quantum_sim.py [app/crates/qcore/src/lib.rs:1-8, 49-53].
qcore/circuit.rs: a general n-qubit statevector simulator with complex amplitudes, used by Atlas pages; MAX_QUBITS = 8 [app/crates/qcore/src/circuit.rs:1-9, 14].
qcore/topic.rs: the Atlas content model and the check gate; the test atlas_content_passes_the_gate reads crates/ui/content and fails on any parse error, wrong outcome or dead link [app/crates/qcore/src/topic.rs:1-5, 186-215].
desktop/main.rs: window, WebView, app:// asset server, IPC dispatch and event loop [app/crates/desktop/src/main.rs:144-279, 330-410].
desktop/pipeline.rs: P1 router, P2 explainer, P3 claim extractor with simulator check and one repair retry, P4 practice; the comment says it has the same control flow as run() in code/workflow.py [app/crates/desktop/src/pipeline.rs:1-2].
desktop/prompts.rs: embeds the four prompt files from prompts/final at compile time with include_str! [app/crates/desktop/src/prompts.rs:24-31]; the comment says the prompt text is &quot;byte-for-byte&quot; what the Python prototype sends [app/crates/desktop/src/prompts.rs:4-5].
desktop/llm/mod.rs: provider abstraction over three wire formats (Gemini native, Anthropic Messages, OpenAI-compatible chat/completions), the preset table, the shared HTTP agent and the retry loop [app/crates/desktop/src/llm/mod.rs:1-6, 17-23, 261-268, 314-375].
desktop/gemini.rs, llm/anthropic.rs, llm/openai.rs: one client per wire format [app/crates/desktop/src/gemini.rs:1-3] [app/crates/desktop/src/llm/anthropic.rs:1] [app/crates/desktop/src/llm/openai.rs:1-2].
desktop/config.rs: key lookup (Credential Manager, environment variable, .env), settings.json for the active provider and chosen models, and the per-user data folder [app/crates/desktop/src/config.rs:1-10, 40-43].
ui/main.rs: mounts the Leptos app, sends hello, renders the title bar, screen switcher and the Settings popover with the key form [app/crates/ui/src/main.rs:17-20, 34-37, 66-85, 159-167].
ui/state.rs: app-wide signals and the handler that applies every host event [app/crates/ui/src/state.rs:83-93, 104-217].
ui/bridge.rs: window.ipc to window.__qe bridge, reduced-motion check and same-document View Transitions [app/crates/ui/src/bridge.rs:1, 8-9, 22-32, 49-66].
ui/atlas.rs, home.rs, tutor.rs, lab.rs, viz.rs, glow.rs: Atlas map and topic pages; scroll-scrubbed Home; Tutor; offline Lab; circle-notation visuals; cursor-following background light [app/crates/ui/src/atlas.rs:1-4] [app/crates/ui/src/home.rs:1-7] [app/crates/ui/src/tutor.rs:1] [app/crates/ui/src/lab.rs:1-2] [app/crates/ui/src/viz.rs:1] [app/crates/ui/src/glow.rs:1-6].

How the UI is built
build.ps1 takes two switches: -Dev (debug build, WebView devtools enabled) and -Run (start the exe after building) [app/build.ps1:1-5]. It detects failures through $LASTEXITCODE, because in Windows PowerShell 5.1 the &quot;Stop&quot; preference would turn cargo&apos;s stderr progress into errors [app/build.ps1:6-8].
cargo +stable-x86_64-pc-windows-gnullvm build -p ui --target wasm32-unknown-unknown, adding --release unless -Dev is given [app/build.ps1:17-18, 23].
Delete and recreate crates\ui\dist and dist\fonts [app/build.ps1:25-27].
wasm-bindgen --target web --no-typescript --out-dir dist --out-name ui target\wasm32-unknown-unknown\&lt;profile&gt;\ui.wasm, which writes ui.js and ui_bg.wasm [app/build.ps1:28] [disk, 25 Nov].
Copy index.html, boot.js and styles\app.css into dist, and every assets\fonts\*.woff2 into dist\fonts [app/build.ps1:30-31].
cargo +stable-x86_64-pc-windows-gnullvm build -p desktop, plus --release unless -Dev, which embeds dist into the exe [app/build.ps1:33-35].
Print the exe path and size in MB, and start the exe if -Run was given [app/build.ps1:36-38].
ui/build.rs generates OUT_DIR/content.rs, which holds include_str! of content/sections.json and every content/topics JSON file in sorted order, with rerun-if-changed for each [app/crates/ui/build.rs:1-23]. atlas.rs includes it [app/crates/ui/src/atlas.rs:15-17] and parses it once in a OnceLock. A file that fails to parse is skipped at run time; the qcore gate test catches it at test time [app/crates/ui/src/atlas.rs:24-31].
desktop/build.rs creates ../ui/dist if it is missing, so cargo test -p desktop compiles on a fresh clone, and sets rerun-if-changed on that folder [app/crates/desktop/build.rs:1-9].
Inference: an exe built while dist is empty answers 404 for every path, including index.html [app/crates/desktop/src/main.rs:56-67].
Page boot chain: index.html preloads two fonts, links app.css and loads boot.js as a module [app/crates/ui/index.html:8-11]. boot.js imports init from ./ui.js and awaits it [app/crates/ui/boot.js:1-3]. The wasm main installs console_error_panic_hook and mounts the App to body [app/crates/ui/src/main.rs:17-20].

Embedding and the app:// protocol
#[derive(Embed)] #[folder = &quot;../ui/dist/&quot;] struct Assets is the embedded file set [app/crates/desktop/src/main.rs:26-28].
rust-embed embeds files only when debug_assertions is off. In a debug build, the generated code reads the folder from disk at run time [registry rust-embed-impl-8.14.0/src/lib.rs:50-56, 258-272]. The desktop crate does not enable the debug-embed feature [app/crates/desktop/Cargo.toml:23]. So the release exe is self-contained, while a -Dev exe still needs crates/ui/dist on disk (inference from these two facts).
serve() strips the leading &quot;/&quot; from the request path and maps an empty path to index.html. It returns the embedded file with a Content-Type from a fixed extension table, Cache-Control: no-cache and the CSP header. Unknown paths get status 404 with the body &quot;not found&quot; [app/crates/desktop/src/main.rs:53-69].
The 404 response carries no CSP or Content-Type header [app/crates/desktop/src/main.rs:67].
MIME table: html &quot;text/html; charset=utf-8&quot;, js &quot;text/javascript; charset=utf-8&quot;, wasm &quot;application/wasm&quot;, css &quot;text/css; charset=utf-8&quot;, svg &quot;image/svg+xml&quot;, woff2 &quot;font/woff2&quot;, png &quot;image/png&quot;, json &quot;application/json&quot;, anything else &quot;application/octet-stream&quot; [app/crates/desktop/src/main.rs:39-51].

Native window
#![windows_subsystem = &quot;windows&quot;] is unconditional (&quot;a GUI app: never open a console window&quot;), so debug builds also have no console [app/crates/desktop/src/main.rs:7].
A panic hook shows a native MessageBoxW (&quot;Something went wrong and the app has to close.&quot;) and then calls process::exit(1) [app/crates/desktop/src/main.rs:304-314, 322]. The release profile uses panic = &quot;abort&quot; [app/Cargo.toml:21].
If window or WebView creation fails, the same message box reads &quot;The window could not start.&quot; with the error and a note that the app needs the Microsoft Edge WebView2 Runtime (&quot;included with Windows 11&quot;) [app/crates/desktop/src/main.rs:323-326].
The event loop is EventLoopBuilder::&lt;UserEvent&gt;::with_user_event(). The user events are Emit(JSON), Minimize, ToggleMaximize, Drag and Close [app/crates/desktop/src/main.rs:30-37, 331].
The four prompts are parsed once at startup and shared through Arc&lt;Prompts&gt; [app/crates/desktop/src/main.rs:333, 269].

Threading model
The main thread runs the tao event loop with ControlFlow::Wait. It owns the window and the WebView, and it applies Emit, Minimize, ToggleMaximize, Drag and Close events [app/crates/desktop/src/main.rs:391-409].
handle_ipc runs synchronously in the wry IPC callback [app/crates/desktop/src/main.rs:383-388]. The comment on save_key (&quot;Check the key with its provider first (off the UI thread)&quot;) implies that the callback itself runs on the UI thread (inference) [app/crates/desktop/src/main.rs:162-163].
These commands do their work inside the callback: hello, which reads settings.json, searches for a .env file and reads the Credential Manager entry for each of the 11 presets [app/crates/desktop/src/main.rs:85-104] [app/crates/desktop/src/config.rs:115-139]; clear_key; set_provider, which writes a file; open_key_page; win; and the settings load at the start of ask [app/crates/desktop/src/main.rs:259].
save_key, list_models and ask each start a detached std::thread::spawn. No handle is kept, so a thread cannot be joined or cancelled [app/crates/desktop/src/main.rs:167, 240, 270].
Worker threads send results back only through EventLoopProxy::send_event(UserEvent::Emit(..)) [app/crates/desktop/src/main.rs:147, 169, 249, 273].
All HTTP is blocking ureq. Each client builds its own ureq::Agent with a global timeout [app/crates/desktop/src/llm/mod.rs:261-268]. Retry waits of 10, 30 and 60 s use std::thread::sleep on the worker thread [app/crates/desktop/src/llm/mod.rs:297, 333, 366].
Shared state across threads: the read-only Arc&lt;Prompts&gt; [app/crates/desktop/src/main.rs:333, 269]; Gemini&apos;s process-wide set of dead models, a LazyLock&lt;Mutex&lt;HashSet&gt;&gt; [app/crates/desktop/src/gemini.rs:12-15]; settings.json, written through a fixed temporary file and a rename with no lock [app/crates/desktop/src/config.rs:57-66, 230-238].
The host does not limit concurrent runs. The only guard is the UI: the Tutor submit button is disabled while run.running is true [app/crates/ui/src/tutor.rs:36-38, 90].

Key storage and settings (architecture view)
Keys are stored in Windows Credential Manager under service &quot;QuantumExplainer&quot; and account &lt;provider&gt;_api_key, so Gemini&apos;s account is gemini_api_key [app/crates/desktop/src/config.rs:4-5, 17, 100-102].
Key lookup order: Credential Manager, then the provider&apos;s process environment variable, then a .env file [app/crates/desktop/src/config.rs:128-139]. The .env search walks every ancestor of the exe&apos;s folder, then every ancestor of the current directory, and the first .env found wins [app/crates/desktop/src/config.rs:68-86].
settings.json at %LOCALAPPDATA%\QuantumExplainer holds only provider and models; it has no field for a key [app/crates/desktop/src/config.rs:9-10, 21-29].
A model id chosen in the UI must be 1 to 200 characters from the set of ASCII letters, digits and ._-/:~@+, and must not contain &quot;..&quot; [app/crates/desktop/src/config.rs:201-208].
Error text and notices are passed through scrub() before they reach the UI. It replaces the key with &quot;…&quot; plus its last four characters [app/crates/desktop/src/llm/mod.rs:250-257, 411-426].
